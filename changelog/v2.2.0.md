# 2.2.0 — In Development

Minecraft 1.21.1 | Fabric, NeoForge

## API

| Tag | Change |
|---:|---|
| ![feature] | `PlaceholderRegistry` — shared player/server placeholder registration; bridges to TAB (Fabric + NeoForge) and Patbox Placeholder API (Fabric) when installed, neither required. Dependent mods no longer need a TAB compile dependency |
| ![feature] | `InputCompat` (shift/control/alt state, window handle, key-down, KeyMapping matching) and `PlayerCompat` (GameProfile name/id) — version-neutral input/profile access for dependent mods (1.21.9 moved these APIs) |
| ![improvement] | `GuiScreen` / `GuiContainerScreen` int-based input methods stay the extension point on every version; on 1.21.9+ the new event-record overrides forward to them |
| ![feature] | `PermissionCompat.hasPermission(CommandSourceStack|Player, int)` — version-neutral op-level check (1.21.11 replaced permission levels with permission sets) |
| ![feature] | `PlayerCompat.sendMessage(player, msg, actionBar)` and `InputCompat.currentModifiers()` — version-neutral replacements for APIs removed in 26.1. `GuiScreen` / `GuiContainerScreen` keep `render` / `renderBackground` as extension points on 26.1 (bridged from `extractRenderState`) |
| ![feature] | `ClientCompat` (`screen()`, `setScreen()`, main render target) and `InputCompat.touchscreen()` — version-neutral client access (26.2 moved screen handling into `Gui` and the main target into `GameRenderer`) |
| ![breaking] | `net.kroia.modutilities.Tuple` replaces `net.minecraft.util.Tuple` (removed in 26.2); `StreamManager` / `StreamSystem.getActive*Streams()` now return it |
| ![improvement] | `WorldGraphics` draws through a `quads(...)` helper so 26.2 can submit deferred geometry via `SubmitNodeCollector` |
| ![improvement] | `gui.InputConstants` key/mouse/modifier values now alias Minecraft's `InputConstants` (26.3 replaced GLFW with SDL3, so all raw values changed); use the names instead of literals like `button == 0`. Added `KEY_SPACE` |
| ![feature] | `InputCompat.isKeyDown` / `isMouseButtonDown` / `setCursorPos` / `containerClickButton`, `PlayerCompat.drop` / `giveOrDrop` — version-neutral input and item-drop access |
| ![improvement] | `AbstractDisplayBlock` provides a `simpleCodec` stand-in on 26.3 (block codecs removed) so subclasses compile unchanged |
| ![removal] | `NetworkPacketC2S` / `NetworkPacketS2C` removed (built on Architectury simple networking, which Architectury 18 removed; unused) |
| ![feature] | `InputConstants.shortcutKey(keyCode, scanCode)` — layout-aware Ctrl+A/C/V/X detection; on 26.3 text-box shortcuts follow the printed letter of the keyboard layout |
| ![feature] | Multi-server handshake carries the slave's Minecraft version; the master rejects a different version with the new `MC_VERSION_MISMATCH` result (checked after the shared secret, appended last to keep the ordinal wire format). Slaves on older ModUtilities send no version and are rejected with a hint to update |
| ![feature] | `RegistryCompat` — version-agnostic `blockProperties`, `itemProperties`, `blockItemProperties`, `createBlockEntityType` (+ public `BlockEntityFactory`); no-ops/`Builder.of` on 1.21.1, apply the registry-ID requirement on 1.21.2+ so dependent mods need no version toggles |

## Internal

| Tag | Change |
|---:|---|
| ![bugfix] | (1.21.6+) GUI items drawn under a custom `Gui` scale (e.g. BankSystem screens at 0.8) were pixelated: vanilla pre-renders GUI items into an atlas at 16 x MC GUI scale px and nearest-resamples that sprite to the scaled size. New `GuiRendererScaledItemsMixin` renders items whose pose is a uniform scale with a whole number of pixels per GUI unit into an extra atlas at that resolution and blits them 1:1 (26.x reuses vanilla `GuiItemAtlas`, 1.21.6-1.21.11 use `ScaledGuiItemAtlas`). Items at scale 1 (vanilla, JEI) are unaffected; 1.21.1-1.21.5 render items directly and need no change |
| ![bugfix] | Custom `Gui` scales (`setGuiScale`) are snapped to whole screen pixels per GUI unit (`round(scale x MC GUI scale) / MC GUI scale`, recomputed on resize/GUI-scale change) so items and textures no longer render pixelated/distorted at fractional ratios (e.g. 0.8 x 3 = 2.4 px). Screens with a custom scale change size slightly (e.g. 0.8 at GUI scale 3 renders as 0.667); `Gui.getGuiScale()` returns the effective scale, `getRequestedGuiScale()` the requested one |
| ![bugfix] | (1.21.4+) GUI scissor rect was offset twice: vanilla 1.21.4 `GuiGraphics.enableScissor` applies the pose matrix to already-absolute coordinates. `ClientGraphics.enableScissor` now scissors with an identity pose |
| ![bugfix] | (1.21.2+) DisplayBlock / RecipeImageExporter rendered into the main framebuffer (vanilla re-binds the main target on every GUI batch flush). The offscreen target is now swapped in as main render target while drawing (`MinecraftAccessor` mixin) |
| ![hardening] | `Signal` / `DataEvent.addListener` ignore an already-registered listener instance, so repeated registration of the same instance can no longer stack |
| ![bugfix] | `StreamManager` server-tick listener was never unregistered; every `StreamSystem.setup()` (once per mod networking + test runs + singleplayer world switches) left the old manager ticking. `setup()` now shuts down the previous manager |
| ![improvement] | Version-agnostic API usage backported from the 1.21.2 port: registry `getOptional(...)` lookups, `lookupOrThrow(...)` enchantment access, enchanted books via `ItemStack.enchant`, `builtInRegistryHolder().tags()`, `displayClientMessage` |
| ![feature] | `GuiGraphicsAccessor` mixin — `ClientGraphics` reads the buffer source via accessor (public getter removed in 1.21.2) |
| ![improvement] | NbtCompat — version-agnostic NBT access (1.21.5 changed CompoundTag getters to Optional); all ModUtilities NBT reads go through it |
| ![improvement] | `AbstractDisplayBlockEntityRenderer` split into prepare/transform/emit steps (1.21.9 render-state renderers); profiler TOTAL no longer includes the quad draw (timed as QUAD_RENDER) |
| ![improvement] | `ClientGraphics.renderOutline` draws four 1px fills itself (vanilla 1.21.9 outline is deferred and ignores pose/scissor) |
| ![improvement] | `level().getServer()` instead of `Entity.getServer()` (removed in 1.21.9) |
| ![bugfix] | Removed all `@Environment(EnvType.CLIENT)` annotations: Architectury turns them into NeoForge `@OnlyIn`, which NeoForge 21.7.3+ reports with a warning screen at startup |
| ![improvement] | 1.21.2+ API variants added as commented `// mc>=1.21.2` toggle lines next to the active `// mc<=1.21.1` lines (ClientGraphics, RecipeImageExporter, AbstractDisplayBlockEntityRenderer, LevelRendererMixin, sandbox registration) so version branches differ only by comment toggles |
| ![feature] | Automated in-game tests: `tools/autotest/run_matrix.py` starts real Fabric/NeoForge instances (singleplayer, multiplayer, slave, slave-singleplayer), runs every mod's `TestRegistry` suites and reports the results. `-Dmodutilities.autotest=<label>` runs a single instance |
| ![hardening] | `enable_dev_features` in `gradle.properties` is the single dev switch: when false, `testing/**` and `sandbox/**` are not compiled and `ENABLE_DEV_FEATURES` turns false automatically, so release jars contain no test or sandbox code |
| ![improvement] | `MultiServerConfig.json` moved to `config/modutilities/`; an existing `config/MultiServerConfig.json` is moved there once on first start |
| ![improvement] | `TestRunner` accepts a null player and keeps all results; setup/teardown failures are reported as errors |
| ![feature] | Test matrix GUI `tools/autotest/matrix_gui.py` (double-click `matrix_gui.bat`): live colour grid of every mod × MC version × loader × config with hover details and Run all / Run not passed / Stop buttons; `run_matrix.py --gui`, shared output folder, per-cell status files, one run at a time. `ADDING_A_VERSION.md` explains adding a new MC version |
| ![bugfix] | Autotest: suites run as a queued server task instead of inside the tick event (Architectury threw `ConcurrentModificationException` when suites registered listeners); the test client dismisses NeoForge's loading-warnings screen (Architectury 17.x `@OnlyIn`, NeoForge 1.21.7/1.21.8) and fails fast on real loading errors; test servers disable the whitelist (on by default in 26.3) |
| ![improvement] | Autotest launch capture moved from `build.gradle` to the Gradle init script `capture.init.gradle`, so BankSystem/StockMarket need no build changes |
| ![feature] | Test matrix GUI: per-cell Play (starts the servers and client of that configuration without tests, until Stop), a chosen template world copied fresh into every Play launch, Clear results, and stale marking when a tested mod jar changed (sha256 per cell); BankSystem rows show the BankSystem results of the StockMarket cells |
| ![improvement] | Autotest builds the jars before each run, clears dependents' Loom remap cache (it kept serving outdated dependency jars) and uses superflat worlds for singleplayer too |
| ![improvement] | Autotest/Play player is always in creative mode |
| ![improvement] | Autotest/Play player is always opped (permission level 4), also in singleplayer worlds with cheats disabled |
| ![feature] | Autotest: test runs can use a template world (`run_matrix.py --world`, GUI **Choose test world...**, separate from **Choose play world...**), copied fresh into every instance of every cell for all MC versions. The test client confirms the open-world prompts itself (backup/upgrade of older worlds on 26.x, upgrade-done), fails fast on incompatible worlds, and a world newer than the cell's MC fails the cell; changing the test world marks results stale |
| ![bugfix] | Singleplayer: display blocks with a GUI lost their block entity on world load ("Rendersystem called from wrong thread"): the integrated server built the display GUI with the client's font-backed fallback graphics. `Gui.getFallbackGraphics()` now hands the client backend only to the thread that installed it; other threads get the headless estimates a dedicated server uses. The display renderer also skips groups whose texture size is 0 (controller not formed/synced yet) instead of crashing with `Invalid texture size: 0x0` |
| ![bugfix] | (1.21.7+) JEI ingredient list was empty on `GuiContainerScreen` screens (BankSystem, StockMarket): JEI 23+ draws it only from inside vanilla's container render, which these screens skip. `GuiContainerScreen` now fires that hook after the GUI (NeoForge container foreground event; JEI's `DRAW_FOREGROUND` on Fabric/Quilt) via `ContainerForegroundHook` |
| ![bugfix] | (1.21.6–1.21.8 Fabric) Rendering a display block crashed the client with "Already transitioned to late registration handler": Fabric API 0.128/0.129 (fabric-rendering-v1 12.4.0) throws from every `GuiRenderer` built after the game's own, which includes `OffscreenGuiRenderer`'s. The new `FabricSpecialGuiElementRegistryMixin` skips Fabric's special-element registration while `OffscreenGuiRenderer` builds its renderer (no-op on NeoForge and other Fabric API builds) |
| ![bugfix] | `CheckBox` checked indicator was sized to half the box and centered with integer division, leaving uneven gaps (1 px short on the right/bottom at some GUI scales). It is now inset 2 px from the box edge: the 1 px frame plus exactly 1 px of empty space on every side |
| ![feature] | Autotest matrix GUI: **Clean build all** (release or dev, one chain ModUtilities → BankSystem → StockMarket per MC version, several versions in parallel), a build column per loader with live `building` state, result and Gradle error excerpt, parallel singleplayer test cells (`--test-jobs`), per-column checkboxes for the automated runs, hidden console windows |
| ![bugfix] | Autotest dev builds also build `:common`, so dependent mods compile against a common jar that contains the test classes (failed after a release build) |
| ![improvement] | Autotest/Play clients open the chat screen after joining: `pauseOnLostFocus:false` left the mouse grabbed while the user worked in other windows; the chat screen frees it without pausing the game (the inventory raced with creative-tab tests) |
| ![feature] | `tools/publish`: CurseForge/Modrinth publisher (CLI + GUI) — game versions read from the jar metadata, refuses dev jars, markdown changelog link, CurseForge manual-release option, local ledger against double uploads, tokens only from environment variables |
