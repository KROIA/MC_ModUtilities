# 2.2.0 — 2026-11-23

Minecraft 1.21.3 | Fabric, NeoForge

## API

| Tag | Change |
|---:|---|
| ![feature] | `PlaceholderRegistry` — shared player/server placeholder registration; bridges to TAB (Fabric + NeoForge) and Patbox Placeholder API (Fabric) when installed, neither required. Dependent mods no longer need a TAB compile dependency |
| ![feature] | `InputCompat` (shift/control/alt state, window handle, key-down, KeyMapping matching) and `PlayerCompat` (GameProfile name/id) — version-neutral input/profile access for dependent mods (1.21.9 moved these APIs) |
| ![improvement] | `GuiScreen` / `GuiContainerScreen` int-based input methods stay the extension point on every version; on 1.21.9+ the new event-record overrides forward to them |
| ![feature] | `PermissionCompat.hasPermission(CommandSourceStack|Player, int)` — version-neutral op-level check (1.21.11 replaced permission levels with permission sets) |
| ![feature] | `PlayerCompat.sendMessage(player, msg, actionBar)` and `InputCompat.currentModifiers()` — version-neutral replacements for APIs removed in 26.1. `GuiScreen` / `GuiContainerScreen` keep `render` / `renderBackground` as extension points on 26.1 (bridged from `extractRenderState`) |
| ![feature] | `ClientCompat` (`screen()`, `setScreen()`, main render target) and `InputCompat.touchscreen()` — version-neutral client access (26.2 moved screen handling into `Gui` and the main target into `GameRenderer`) |
| ![breaking] | `net.kroia.modutilities.Tuple` replaces `net.minecraft.util.Tuple` (removed in 26.2); `StreamManager` / `StreamSystem.getActive*Streams()` now return it |
| ![improvement] | `WorldGraphics` draws through a `quads(...)` helper so 26.2 can submit deferred geometry via `SubmitNodeCollector` |
| ![improvement] | `gui.InputConstants` key/mouse/modifier values now alias Minecraft's `InputConstants` (26.3 replaced GLFW with SDL3, so all raw values changed); use the names instead of literals like `button == 0`. Added `KEY_SPACE`. Focused text boxes start SDL3 text input (`InputCompat.setTextInputFocus`) |
| ![feature] | `InputCompat.isKeyDown` / `isMouseButtonDown` / `setCursorPos` / `containerClickButton`, `PlayerCompat.drop` / `giveOrDrop` — version-neutral input and item-drop access |
| ![improvement] | `AbstractDisplayBlock` provides a `simpleCodec` stand-in on 26.3 (block codecs removed) so subclasses compile unchanged |
| ![removal] | `NetworkPacketC2S` / `NetworkPacketS2C` removed (built on Architectury simple networking, which Architectury 18 removed; unused) |
| ![feature] | `InputConstants.shortcutKey(keyCode, scanCode)` — layout-aware Ctrl+A/C/V/X detection; on 26.3 text-box shortcuts follow the printed letter of the keyboard layout |
| ![feature] | Multi-server handshake carries the slave's Minecraft version; the master rejects a different version with the new `MC_VERSION_MISMATCH` result (checked after the shared secret, appended last to keep the ordinal wire format). Slaves on older ModUtilities send no version and are rejected with a hint to update |
| ![bugfix] | `TextBox.setText(double)` rounds to 4 decimals and strips trailing zeros (`0.3f` showed as `0.30000001192092896`). New overloads `setText(double, int maxDecimalPlaces)` and `setText(double, String format)` for other precisions; whole numbers now show without `.0` |
| ![feature] | `RegistryCompat` — version-agnostic `blockProperties`, `itemProperties`, `blockItemProperties`, `createBlockEntityType` (+ public `BlockEntityFactory`); no-ops/`Builder.of` on 1.21.1, apply the registry-ID requirement on 1.21.2+ so dependent mods need no version toggles |
| ![feature] | `PermissionCompat.registerNode(node, fallbackLevel)` + `hasPermission(CommandSourceStack|ServerPlayer, node, fallbackLevel)` — named permission nodes controllable by LuckPerms or any permission mod (NeoForge `PermissionAPI`, Fabric/Quilt `fabric-permissions-api`); falls back to the op-level check when no permission mod decides, for console sources, and for unregistered nodes |
| ![feature] | `LuckPermsBridge` (optional, only active when LuckPerms is installed): `setNode(uuid, node, value)` writes a user permission (offline users too, pushed to other servers via LuckPerms messaging) and `addNodeChangeListener(node, listener)` reports effective value changes (user, group, web editor, cross-server) on the server thread. `getEffective(uuid, node)` returns the effective value (online or offline users), e.g. to detect a group still granting a node after `setNode(..., false)`. All `setNode`, `getEffective` and change-check calls for one player run one after another, in call order. Listeners can be added any time, also from server-start handlers. LuckPerms is a compile-only dependency and never bundled |
| ![feature] | `DiscordWebhooks` (optional, inert until configured): mods register message types and post events; admins route each type to one or more named webhooks in `config/modutilities/discord/` (`webhooks.json` + one file per mod), with per-language templates (en_us/de_de/zh_cn shipped by each mod), `minAmount` filter, batching and Discord rate-limit handling; mentions are always disabled and webhook URLs never leave the config files. `DiscordWebhooks.command()` gives the `discord reload\|status` node for mods to attach under their own command (e.g. `/<mod> discord status`); it is also available as `/modutilities discord`. Every attachment shows the same overview of all mods: per type its state, webhook names and `minAmount`, never URLs, plus a hint on slave servers that the master sends the posts (node `modutilities.command.discord`, fallback op level 3) |
| ![feature] | ARRS request failures, off by default, turned on with `RequestManager.ENABLE_REQUEST_FAILURES = true`: requests time out after `GenericRequest.getTimeoutMs()` (default 30 s, checked every 20 server and client ticks); a master/slave send that is refused fails at once; a lost master/slave connection fails the requests sent over it at once. Client requests forwarded by a slave fail at once too: `RequestNotSentException` when the slave cannot reach the master, `RequestOutcomeUnknownException` when the slave↔master link drops after forwarding (`GenericResponsePacket` carries a status byte) |
| ![feature] | `RequestOutcomeUnknownException` (extends `TimeoutException`): the request was sent, then timed out or the connection was lost, so the receiver may have handled it. `RequestNotSentException` (extends `IllegalStateException`): a master/slave request was never sent, so refunding is safe. A `null` result still means no buffer could be created (nothing sent) |
| ![breaking] | `RequestManager.cleanupExpiredRequests(long maxAgeMs)` replaced by `cleanupExpiredRequests(boolean clientSide)` (per-request timeouts); client requests now fail with `RequestOutcomeUnknownException` instead of a plain `TimeoutException`. The old method was never called |
| ![breaking] | `DropDownMenu.addOption(String)` returns the created `Label` (was `void`), e.g. to attach a tooltip |
| ![bugfix] | Multi-server: a slave routes master-bound packets, requests and streams by its role, not its link state. While the master is down they are no longer handled on the slave itself (dependent handlers ran there and failed, logged stack traces and left clients waiting); requests fail with `RequestNotSentException` (with `RequestManager.ENABLE_REQUEST_FAILURES`), other packets are dropped, streams end via the client's stopped handler, and streams the slave was relaying when the link drops are stopped the same way. The "not connected" error is one line at most every 30 s; the slave's connection-lost callback also fires once when an established link drops |
| ![removal] | The in-game test framework (`TestSuite`, `TestRegistry`, `TestRunner`, `TestResult`, `TestCategory` and the test commands) is no longer part of ModUtilities; release jars contain no test code. |
| ![feature] | `GuiElement.getRenderedChilds()` — the child elements the element actually draws (e.g. only the selected tab's content, the visible list rows) |
| ![bugfix] | `DataPersistence` saves are crash-safe: single NBT/JSON files are written to `<file>.tmp` and renamed over the target; `saveDataCompoundList` (and so `saveDataCompoundListMap`) writes all chunks to `<name>.tmp` and only then swaps it in (`<name>` → `<name>.old` → delete), instead of deleting the old chunks first. A crash or I/O error keeps the previous data; loads read `<name>.old` when `<name>` is missing and ignore `.tmp` folders. File layout unchanged. `NBTFileParser.saveDataCompound` writes the same way |
| ![bugfix] | `DataPersistence` chunked saves/loads strip only a trailing `.nbt` from the name (and `.old` when recovering a map entry), so dotted names like `a.b` round-trip instead of being cut to `a`. Existing folder names unchanged |
| ![feature] | `MultiServerManager.getIdentity()` → `IServerIdentity` (`serverUid`, `role` STANDALONE/MASTER/SLAVE, `slaveId`, `masterUid`, `slaveUid(slaveId)`), persisted in `<world>/data/ModUtilities/server_identity.json` (written atomically, only on change; a corrupt file starts a new identity). Role and slave ID come from `createMaster`/`createSlave`; a changed slave ID generates a new uid. The handshake exchanges the uids in backward-compatible trailing fields (slaves without one are accepted with a warning) and the master rejects a slave whose uid belongs to itself or another known slave with the new `DUPLICATE_SERVER_UID` result (appended last; a reconnect under the same slave ID is exempt). Diagnostics only, never used for authorization |

## UI/UX

| Tag | Change |
|---:|---|
| ![bugfix] | `CreativeModeItemSelectionScreen` closed via ESC/cancel no longer re-centers the mouse cursor: the cursor position is restored after the close callback has opened its screen |
| ![feature] | Library GUI scale, client setting `gui.guiScale` in `config/modutilities/ClientConfig.json`: 0 = auto (default), library screens ignore Minecraft's GUI scale and use the largest scale that fits the window (what Minecraft's "auto" picks), adapting on resize; -1 follows Minecraft's GUI scale; N draws library screens at N pixels per GUI unit, capped to fit the window. In any library screen (no text box focused) Ctrl + `+` / `-` step the scale and Ctrl + `0` toggles auto / follow Minecraft; applied live, saved to the file, with a short "GUI scale: Auto (4)" hint. Per-screen `setGuiScale` values still multiply on top |
| ![bugfix] | `ListView` keeps its scroll position when its rows are cleared and re-added (periodic list refreshes no longer jump back to the top); refilling with fewer rows clamps to the new end |
| ![bugfix] | `DropDownMenu` options that open outside the menu's parent now get hover highlight, tooltips, scroll wheel and scrollbar drag; hover and clicks share one hit test, so options hidden by an enclosing `ListView` (scrolled out or clipped) no longer react to clicks |
| ![improvement] | `DropDownMenu`: picking an option collapses the menu and shows the option's text in the collapsed label (before the callback runs), the selected row is highlighted when the menu reopens, and a click on an open option no longer reaches an element underneath that was added earlier |
| ![feature] | `FeatureToggleSection`: expandable feature row with an enable checkbox, greyed-out child settings while disabled, a darker background while expanded so you can see which rows belong to it (`setBackgroundColor` changes it), a "Restart required" marker (`setRestartMarkerText(text, tooltip)` sets its own wording, e.g. a static "only read at server start" marker) and a locked state ("Runs on the master server only"). `GuiElement.setInteractive(false)` keeps an element visible but blocks input and greys it out. New Chinese (zh_cn) translation file for the new texts |
| ![feature] | Hover tooltips: opt-in `HoverTooltipData.autoSide` (tooltip opens away from the nearer screen edge: left half of the screen to the right of the cursor, right half to the left; vertical alignment kept) and `maxWidthFraction` (word-wraps the text to at most that fraction of the screen width, keeping `\n` breaks). Also available on `TooltipData` for `drawTooltip(TooltipData)` |
| ![bugfix] | Text tooltips (hover tooltips and `drawTooltip(String, ...)`) are kept inside the screen, background padding included; a tooltip larger than the screen is pinned to the top-left edge |
| ![bugfix] | `TabElement` switches to the tab under the click position instead of the tab under the cursor position of the last drawn frame |
| ![feature] | `ScreenNotice`: a short message in larger red text, centred over the open library screen and wrapped to fit it, shown for 5 seconds, for warnings that would go unnoticed in the chat behind a screen. `ScreenNotice.show(Component)` on the client, `ScreenNotice.send(ServerPlayer, Component)` from the server |

| Tag | Change |
|---:|---|
| ![improvement] | Version bumped to 2.2.0 (cleanup/polish release, replaces planned 2.1.3); groundwork for shipping on every Architectury-supported MC version above 1.21.1 |

| ![bugfix] | NeoForge: ModUtilities runs its setup from the mod-construction work queue instead of the mod constructor. | ![improvement] | Release jars no longer ship the sandbox demo blocks' blockstates and models (`*_demo_*`, only in dev builds) or GIMP source files (`*.xcf`) |

## Internal

| Tag | Change |
|---:|---|
| ![bugfix] | Custom `Gui` scales (`setGuiScale`) are snapped to whole screen pixels per GUI unit (`round(scale x screen GUI scale) / screen GUI scale`, recomputed on resize/GUI-scale change) so items and textures no longer render pixelated/distorted at fractional ratios (e.g. 0.8 x 3 = 2.4 px). Screens with a custom scale change size slightly (e.g. 0.8 at GUI scale 3 renders as 0.667); `Gui.getGuiScale()` returns the effective scale, `getRequestedGuiScale()` the requested one |
| ![hardening] | `Signal` / `DataEvent.addListener` ignore an already-registered listener instance, so repeated registration of the same instance can no longer stack |
| ![bugfix] | `StreamManager` server-tick listener was never unregistered; every `StreamSystem.setup()` (once per mod networking + test runs + singleplayer world switches) left the old manager ticking. `setup()` now shuts down the previous manager |
| ![improvement] | Version-agnostic API usage backported from the 1.21.2 port: registry `getOptional(...)` lookups, `lookupOrThrow(...)` enchantment access, enchanted books via `ItemStack.enchant`, `builtInRegistryHolder().tags()`, `displayClientMessage` |
| ![feature] | `GuiGraphicsAccessor` mixin — `ClientGraphics` reads the buffer source via accessor (public getter removed in 1.21.2) |
| ![improvement] | NbtCompat — version-agnostic NBT access (1.21.5 changed CompoundTag getters to Optional); all ModUtilities NBT reads go through it |
| ![improvement] | `AbstractDisplayBlockEntityRenderer` split into prepare/transform/emit steps (1.21.9 render-state renderers); profiler TOTAL no longer includes the quad draw (timed as QUAD_RENDER) |
| ![improvement] | `ClientGraphics.renderOutline` draws four 1px fills itself (vanilla 1.21.9 outline is deferred and ignores pose/scissor) |
| ![improvement] | `level().getServer()` instead of `Entity.getServer()` (removed in 1.21.9) |
| ![improvement] | Removed all `@Environment(EnvType.CLIENT)` annotations: Architectury turns them into NeoForge `@OnlyIn`, which NeoForge 21.7.3+ reports with a warning screen at startup |
| ![improvement] | 1.21.2+ API variants added as commented `// mc>=1.21.2` toggle lines next to the active `// mc<=1.21.1` lines (ClientGraphics, RecipeImageExporter, AbstractDisplayBlockEntityRenderer, LevelRendererMixin, sandbox registration) so version branches differ only by comment toggles |
| ![hardening] | `enable_dev_features` in `gradle.properties` is the single dev switch: when false, `testing/**` and `sandbox/**` are not compiled and `ENABLE_DEV_FEATURES` turns false automatically, so release jars contain no test or sandbox code |
| ![improvement] | `MultiServerConfig.json` moved to `config/modutilities/`; an existing `config/MultiServerConfig.json` is moved there once on first start |
| ![hardening] | `Gui.getFallbackGraphics()` hands the client's font-backed backend only to the thread that installed it; other threads (e.g. the singleplayer integrated server building display GUIs) get the headless estimates a dedicated server uses, since the client font is not thread-safe. The display renderer skips groups whose texture size is 0 (controller not formed/synced yet) |
| ![bugfix] | `CheckBox` checked indicator was sized to half the box and centered with integer division, leaving uneven gaps (1 px short on the right/bottom at some GUI scales). It is now inset 2 px from the box edge: the 1 px frame plus exactly 1 px of empty space on every side |
