# 2.2.0 — In Development

Minecraft 1.21.1 | Fabric, NeoForge

## API

| Tag | Change |
|---:|---|
| ![feature] | `PlaceholderRegistry` — shared player/server placeholder registration; bridges to TAB (Fabric + NeoForge) and Patbox Placeholder API (Fabric) when installed, neither required. Dependent mods no longer need a TAB compile dependency |
| ![feature] | `RegistryCompat` — version-agnostic `blockProperties`, `itemProperties`, `blockItemProperties`, `createBlockEntityType` (+ public `BlockEntityFactory`); no-ops/`Builder.of` on 1.21.1, apply the registry-ID requirement on 1.21.2+ so dependent mods need no version toggles |

## Build & Dependencies

| Tag | Change |
|---:|---|
| ![improvement] | Version bumped to 2.2.0 (cleanup/polish release, replaces planned 2.1.3); groundwork for shipping on every Architectury-supported MC version above 1.21.1 |
| ![breaking] | 26.1 build now targets Minecraft 26.1.2 and needs NeoForge 26.1.2.21 or newer: every Architectury 20.x release uses NeoForge's `BreakBlockEvent`, which older NeoForge lacks (startup crash). Architectury 20.1.17, NeoForge 26.1.2.126, Fabric API 0.155.3+26.1.2, JEI 29.53.0.115; MC 26.1 / 26.1.1 no longer supported |

## Internal

| Tag | Change |
|---:|---|
| ![bugfix] | (1.21.4+) GUI scissor rect was offset twice: vanilla 1.21.4 `GuiGraphics.enableScissor` applies the pose matrix to already-absolute coordinates. `ClientGraphics.enableScissor` now scissors with an identity pose |
| ![bugfix] | (1.21.2+) DisplayBlock / RecipeImageExporter rendered into the main framebuffer (vanilla re-binds the main target on every GUI batch flush). The offscreen target is now swapped in as main render target while drawing (`MinecraftAccessor` mixin) |
| ![hardening] | `Signal` / `DataEvent.addListener` ignore an already-registered listener instance, so repeated registration of the same instance can no longer stack |
| ![bugfix] | `StreamManager` server-tick listener was never unregistered; every `StreamSystem.setup()` (once per mod networking + test runs + singleplayer world switches) left the old manager ticking. `setup()` now shuts down the previous manager |
| ![improvement] | Version-agnostic API usage backported from the 1.21.2 port: registry `getOptional(...)` lookups, `lookupOrThrow(...)` enchantment access, enchanted books via `ItemStack.enchant`, `builtInRegistryHolder().tags()`, `displayClientMessage` |
| ![feature] | `GuiGraphicsAccessor` mixin — `ClientGraphics` reads the buffer source via accessor (public getter removed in 1.21.2) |
| ![improvement] | 1.21.2+ API variants added as commented `// mc>=1.21.2` toggle lines next to the active `// mc<=1.21.1` lines (ClientGraphics, RecipeImageExporter, AbstractDisplayBlockEntityRenderer, LevelRendererMixin, sandbox registration) so version branches differ only by comment toggles |
| ![feature] | Automated in-game tests: `tools/autotest/run_matrix.py` starts real Fabric/NeoForge instances (singleplayer, multiplayer, slave, slave-singleplayer), runs every mod's `TestRegistry` suites and reports the results. `-Dmodutilities.autotest=<label>` runs a single instance |
| ![hardening] | `enable_dev_features` in `gradle.properties` is the single dev switch: when false, `testing/**` and `sandbox/**` are not compiled and `ENABLE_DEV_FEATURES` turns false automatically, so release jars contain no test or sandbox code |
| ![improvement] | `MultiServerConfig.json` moved to `config/modutilities/`; an existing `config/MultiServerConfig.json` is moved there once on first start |
| ![improvement] | `TestRunner` accepts a null player and keeps all results; setup/teardown failures are reported as errors |
| ![feature] | Test matrix GUI `tools/autotest/matrix_gui.py` (double-click `matrix_gui.bat`): live colour grid of every mod × MC version × loader × config with hover details and Run all / Run not passed / Stop buttons; `run_matrix.py --gui`, shared output folder, per-cell status files, one run at a time. `ADDING_A_VERSION.md` explains adding a new MC version |
| ![bugfix] | Autotest: suites run as a queued server task instead of inside the tick event (Architectury threw `ConcurrentModificationException` when suites registered listeners); the test client dismisses NeoForge's loading-warnings screen (Architectury 17.x `@OnlyIn`, NeoForge 1.21.7/1.21.8) and fails fast on real loading errors; test servers disable the whitelist (on by default in 26.3) |
| ![improvement] | Autotest launch capture moved from `build.gradle` to the Gradle init script `capture.init.gradle`, so BankSystem/StockMarket need no build changes |
| ![feature] | Test matrix GUI: per-cell Play (starts the servers and client of that configuration without tests, until Stop), a chosen template world copied fresh into every Play launch, Clear results, and stale marking when a tested mod jar changed (sha256 per cell); BankSystem rows show the BankSystem results of the StockMarket cells |
| ![improvement] | Autotest builds the jars before each run, clears dependents' Loom remap cache (it kept serving outdated dependency jars) and uses superflat worlds for singleplayer too |
