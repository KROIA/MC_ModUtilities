# 2.0.6 — In Development

Minecraft 1.21.1 | Fabric, NeoForge

## Performance

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Display renderer collisions when multiple block-entity types share a group</summary><br>**Root cause:** each BE type registers its own `AbstractDisplayBlockEntityRenderer` instance, each holding a private `groupData` map and creating a `DynamicTexture` registered at the shared location `dynamic/display_group_X_Y_Z`. In a mixed-type group, the second registration evicted the first from `TextureManager`, so all block faces sampled the last-registered texture and the other renderer's writes were invisible. On top of that, the renderer that ran first each frame called `gui.clearAllDirty()`, leaving the second renderer to see a clean gui and skip; and each renderer used its own block's `getDisplayConfig()`, so throttle/LOD decisions disagreed within a group.<br><br>**Fix:** `groupData` is now `static` — shared across all renderer instances so there is exactly one texture per group regardless of BE type count. The controller BE is resolved once at the top of `render()`; `DisplayConfig`, group dimensions, and gui are all sourced from the controller (deterministic controller-wins semantics). The dirty-flag race resolves automatically because only one call per frame per controller position enters the render branch.</details> |
| ![bugfix] | Display renderer: initial render now always fires regardless of `maxRenderDistance`. Previously, blocks placed while the player was beyond the cutoff never rendered content into their texture, leaving driver-defined uninitialized GPU memory (typically black) until the player walked into range. |

## API

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>New GUI API: screens can hide JEI's overlay or specific overlay buttons while open</summary><br>Screens extending `GuiScreen` / `GuiContainerScreen` can now opt into hiding JEI's ingredient list + bookmark overlays (`setHideJeiOverlay(true)`) or only named overlay buttons like the config gear / bookmark toggle / lookup-history toggle (`setHideJeiButtons(String...)`) while they are open. Set it once in the subclass constructor and the base class handles hide-on-open, hide-on-resize (idempotent), and restore-on-close automatically.<br><br>Safe when JEI is absent — the broker no-ops. Screens that don't opt in are unchanged. Adds JEI as a soft dev-runtime dependency on Fabric and NeoForge so the platform transformer can resolve the reflected JEI types at launch.</details> |
| ![bugfix] | <details><summary>`ServerPlayerUtilities.addToPlayerInventory` merged stacks by raw item type, ignoring data components</summary><br>**Root cause:** The merge-target predicate was `currentStack.is(stackCpy.getItem())` — plain item-type equality. Two stacks of the same item with different data components (enchantments, damage, custom name, TFC `tfc:food` decay state, etc.) were merged into one stack, silently rewriting the inserted items' state to match the existing stack. Vanilla `Inventory.add` uses `ItemStack.isSameItemSameComponents` and mods (e.g. TerraFirmaCraft) mixin that method to define stateful merge semantics — component-blind merging bypassed all of that.<br><br>**Fix:** merge predicate now `ItemStack.isSameItemSameComponents(currentStack, stackCpy)` — matches vanilla contract and respects mod hooks that gate merging on component state. Count / max-size math and the mutation contract on the input `stack` (dependent mods rely on `stack.setCount(remainingAmount)` for overflow handling) are unchanged.</details> |

## UI / UX

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>`TextBox` crashed with `StringIndexOutOfBoundsException` on Backspace/Delete when a prior selection had gone stale</summary><br>**Root cause:** `TextBox.setText(String)` clamped the cursor to the new text length but never reset `selectionCursonIdxStart` / `selectionCursonIdxEnd`. Any external caller that shortened the text while a selection was active (e.g. an `onTextChanged` callback in a dependent mod) left the selection pointing past the current text length. The next Backspace / Delete / character-insert executed `text.substring(0, staleStart) + text.substring(staleEnd)` and threw `Range [3, 0) out of bounds for length 0`, crashing the client to the error screen.<br><br>**Fix:** `setText` now clears the selection. A new `hasValidSelection()` helper bounds-checks both indices against the current `text.length()`; all seven selection-slice sites (Ctrl+C, Ctrl+X, paste-with-regex, paste-mutate, Backspace, Delete, char-typed) route through it and order-normalize the selection into `s = min(start, end)` / `e = max(start, end)` before slicing — as a side benefit, this also fixes latent breakage on reversed (shift+left) selections.</details> |

## Internal

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>Sandbox `DisplayDemoBlock` animation was invisible on the client</summary><br>`AbstractDisplayBlockEntity.serverTick()` runs on both server and client, so `onControllerTick()` ticks on both — animation can be entirely client-local, no network sync required. But `wireCallbacks()` (which sets the `plot` field) is gated to server-only, so the client's `plot` reference stayed null and `onControllerTick()` returned early. Now the demo lazy-resolves `plot` from `gui.getElements()` every tick — handles both initial null on the client AND stale references after `rebuildGui()` (group formation/dissolution). Zero network traffic for the animation.</details> |
| ![improvement] | <details><summary>Sandbox: perf-tuned display block variant + repro test commands</summary><br>New sandbox block `display_demo_perf_block` uses `DisplayConfig.fullBlock(256, 256, 10, 24)` — a `renderInterval=10` (2 Hz redraw throttle) + `maxRenderDistance=24` blocks LOD cutoff — for A/B testing the framework's per-block performance knobs against a baseline `display_demo_block`. Two new commands: `/modutilities giveDisplayPerfBlock` gives the perf variant; `/modutilities testInventoryMerge` reproduces the `ServerPlayerUtilities.addToPlayerInventory` component-aware merge scenario. `ExampleFormScreen` gains a Clear button that calls `setText("")` on the three fields externally — the exact trigger for the TextBox stale-selection crash fix in v2.0.6.</details> |
